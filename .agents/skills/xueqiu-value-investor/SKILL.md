# 雪球价值投资日课

## 核心原则

- 把雪球当作线索源，不当作事实终点。
- 把热度与投资价值分开；买股票等于买公司。
- 不承诺收益，不制造紧迫感，不复制他人长文。
- 对发布帖子、评论等外部沟通，在最终提交前执行浏览器所要求的确认。
- 不自动处理验证码、密码、短信验证码或风控验证。

## 每日流程

1. 使用 Browser 技能打开 `https://xueqiu.com/`，复用用户现有登录态。若未登录，停在登录页并请用户登录。
2. 记录账号名、关注数、粉丝数，作为当日增长基线；不得读取 cookie、密码或本地存储。
3. 将信息源严格拆成两个独立部分，不混合统计：
   - **关注流**：浏览 10–20 条关注账号的原创或高互动内容，记录作者、原帖 URL、公司/行业、催化、关键数字、反方观点与发布时间；重点人物动态优先放入这一部分。
   - **热门流**：浏览热门话题前 8 条及相关高互动原帖，记录话题、作者、原帖 URL、热度信号、公司/行业、催化、关键数字与反方观点。
   - 每条线索必须标注 `来源：关注流` 或 `来源：热门流`。同一事件在两处出现时，保留两条来源记录，再在汇总中说明“交叉出现”，不得当作两份独立事实。
4. 先分别对关注流和热门流的候选机会执行价值过滤：生意模式、护城河、管理层、现金流、负债、周期位置、估值、安全边际。使用 [evaluation.md](references/evaluation.md) 的评分表；热门流的高热度不能提高评分。
5. 对会影响投资判断的最新事实，优先核验公司公告、交易所文件、财报等一手来源；雪球内容只标记为“待核验线索”。
6. 生成三项交付：
   - 一篇 800–1500 字长文草稿，或 1–3 条有实质增量的评论草稿；
   - 当日投资观察 HTML；
   - 次日跟踪清单。
7. 将 HTML 保存为 `07-雪球研究/每日观察/雪球价值观察-YYYY-MM-DD.html`。使用浅色背景、章节折叠、二级 `<details>`，并按以下顺序包含：关注流观察、热门流观察、交叉验证与线索雷达、段永平三问、证据/反证、操作建议和风险声明。每个来源部分至少列出样本范围、原帖链接、待核验项与独立结论；不得用热门榜替代关注流，也不得把两者合并为未标注的“市场观点”。
   - 若发现可复核且有投资意义的线索，在 HTML 顶部加入唯一的 `<div class="desc">`，用 40–90 字概述“来源 + 线索 + 当前分级/下一步验证”；发布脚本会将其显示在 `reports.html` 卡片。
   - 若只有噪声、泛观点或无法形成研究行动的内容，不添加 `.desc`，让 `reports.html` 卡片不显示摘要；不得为填满摘要而输出结论。
8. 运行 `scripts/publish_reports.py`，确认文件被复制到 `D:\AI\stock-theme-assistant\www\reports\` 且 `www/reports.html` 出现当日卡片。
9. 分别检查两个仓库的 diff，只提交本流程新增或修改的文件；保留用户原有未提交文件。依次 commit、push。
10. 访问 `https://stock.futuretime.site/reports.html` 验证线上卡片和报告可打开。若站点部署不是由 push 自动触发，明确报告尚未上线并给出所需部署动作。

## 机会分级

- `研究`：商业模式可能优秀，关键数据仍需核验。
- `观察`：逻辑成立但价格或周期位置缺少安全边际。
- `候选买入`：一手数据支持、估值方法交叉验证且有足够安全边际。
- `回避`：无法理解、治理存疑、负债/现金流恶化，或主要依赖叙事与博弈。

仅凭单日雪球内容，最高给到“研究”或“观察”；升级为“候选买入”必须完成独立财务与估值核验。

## 互动规范

- 评论必须回应原帖的具体观点，并至少增加一个框架、数据问题或反证。
- 不批量刷屏，不复制同一评论，不硬塞网站链接，不冒充已核验事实。
- 长文采用“反常识钩子—证据—反证—估值/行动—风险”的结构。
- 未经当次确认，不点击最终“发布”按钮；可先填写草稿并停在提交前。

## 失败处理

- 登录失效：请用户在所选浏览器登录后继续。
- 遇到验证码：说明具体页面并请求用户决定是否处理。
- 页面结构变化：重新取 DOM 快照，从可见标签构建定位，不猜选择器。
- 发布脚本失败：停止 push，保留生成文件，报告失败命令与错误。
- Git 工作树有无关修改：只暂存本流程文件；重叠冲突时请求用户处理。
